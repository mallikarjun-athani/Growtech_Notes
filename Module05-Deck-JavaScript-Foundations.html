JavaScript foundationsMaking the page think

HTML says what things are. CSS says how they look. JavaScript decides what happens — when a button is pressed, when a form is wrong, when data arrives. It is also the one language you will use in every layer of the MERN stack, from the browser to the server.

Part 1 · Where it fits

Three languages, three jobs

This is why JavaScript matters for placement: in a MERN job you write it in the browser (React), on the server (Express on Node) and in the database queries (MongoDB). One language, three layers. Nothing you learn in this module is wasted.
JavaScript is not Java. The name was a 1995 marketing decision. They share some syntax and nothing else. Saying "Java script" in an interview is a small, avoidable red flag.
Part 1 · First program

console.log is how you see what the code is doing

console.log("Hello from JavaScript");
console.log(2 + 3);
console.log("2" + "3");

Press Run. Notice 2 + 3 and "2" + "3" give different answers — the quotes change everything. That is the first lesson of this module, and we will come back to it.

Where the script goes in a real page 
<!-- at the end of <head>, with defer -->
<script src="js/app.js" defer></script>
  • In its own file, linked with src — the same reason CSS goes in its own file: it is cached, and it stays out of your markup.
  • With defer. The browser downloads it while building the page and runs it once the HTML is ready. Without it, the page stops loading while the script downloads.
  • Press F12 in any browser and open the Console tab. That is where console.log writes — and where every error will appear.
Part 1 · Variables

A variable is a labelled box that holds a value

KeywordCan you put a new value in the box?Where does it exist?Use it
constNo — the label is glued to one valueInside the nearest { }By default. Most values never change.
letYesInside the nearest { }When the value genuinely changes — a counter, a running total.
varYesThe whole function, ignoring { }Never in new code. You will read it in old code.
live · edit and run
const course = "Full Stack";
let seatsFilled = 38;

seatsFilled = seatsFilled + 1;   // fine: let can change
console.log(course, seatsFilled);

course = "Data Science";         // not fine
console.log(course);
Run it and read the error. The first two lines print, then JavaScript stops at course = … with "Assignment to constant variable". Errors are not failures — they are the language telling you precisely which rule you broke.
The habit to build now: write const first, every time. Only change it to let when the code actually needs to reassign it. Your code then tells the reader which values can move.
Part 1 · Naming

Rules the language enforces, conventions the industry enforces

Rules — break these and the code will not run
  • Letters, digits, _ and $ only — no spaces, no hyphens
  • Cannot start with a digit: 2ndPlace is an error
  • Cannot be a reserved word: let, if, class, return
  • Case-sensitive: total and Total are two different boxes
Conventions — break these and code review will
  • camelCase for variables and functions: seatsFilled, getTotal
  • UPPER_SNAKE for fixed settings: MAX_SEATS, TAX_RATE
  • Booleans read as a question: isLoggedIn, hasPaid
  • Say what it holds, not what type it is: price, never num1
live · edit and run
let userName = "Asha";
let username = "Ravi";
console.log(userName, username);   // two different variables

const MAX_SEATS = 50;
const isFull = 38 >= MAX_SEATS;
console.log("Batch full?", isFull);

Part 1 · Strings

Strings — and the only quotes you need

  • 'single' and "double" quotes are identical. Pick one and be consistent.
  • Backticks — template literals — are the ones to reach for. They drop values straight into text with ${ }, and they can span several lines.
  • A string is a sequence of characters, counted from zero. .length tells you how many.
  • String methods return a new string. They never change the original — strings in JavaScript cannot be modified.
live · edit and run
const name = "Asha";
const seat = 12;

// the old way — easy to get the spaces wrong
console.log("Hello " + name + ", seat " + seat);

// the way to write it
console.log(`Hello ${name}, seat ${seat}`);

const city = "Indore";
console.log(city.length);        // 6
console.log(city[0], city[5]);   // counted from 0
console.log(city.toUpperCase());
console.log(city.includes("do"));
console.log("  padded  ".trim());
Part 1 · Numbers

Numbers — one type, and two surprises

live · edit and run
console.log(10 / 3);
console.log(0.1 + 0.2);          // surprise one

console.log(Number("42"));       // text to number
console.log(Number("42px"));     // surprise two: NaN
console.log(parseInt("42px"));   // reads until it can't

console.log(Math.round(4.6), Math.floor(4.6), Math.ceil(4.1));
console.log((1299.5).toFixed(2)); // money: always 2 places
  • 0.1 + 0.2 is not exactly 0.3. Computers store decimals in binary, and 0.1 has no exact binary form — just as 1/3 has no exact decimal form. Every language has this, not just JavaScript.
  • NaN means "Not a Number" — the result of maths that made no sense, like turning "42px" into a number. Its typeof is, confusingly, "number".
  • Values from a form are always strings, even when the user types digits. Convert with Number() before doing arithmetic — or "5" + 1 gives you "51".
For money, never trust a decimal result directly. Work in whole paise and divide at the end, or format with toFixed(2) for display.

Part 2 · Comparison

== versus === — the most-asked question in JavaScript interviews

Comparison== loose=== strict
5 vs "5"truefalse
0 vs ""truefalse
0 vs falsetruefalse
null vs undefinedtruefalse
"1" vs truetruefalse
NaN vs NaNfalsefalse

== converts both sides to a common type first, using rules almost nobody can recite. === checks the value and the type, with no conversion.

live · edit and run
console.log(5 == "5");     // true  — converted first
console.log(5 === "5");    // false — different types

console.log(0 == "");      // true  — really
console.log(0 === "");     // false

const age = "18";          // from a form: a string!
if (age === 18) {
  console.log("adult");
} else {
  console.log("did not match — convert first");
}
console.log(Number(age) === 18);
The rule, with no exceptions for beginners: always use === and !==. When the types might differ, convert deliberately with Number() or String() first — so the conversion is written down where the next person can see it.
Part 2 · Coercion

Why "5" + 3 and "5" − 3 give different answers

live · edit and run
console.log("5" + 3);     // "53"
console.log("5" - 3);     // 2
console.log("5" * "2");   // 10
console.log("5" + 3 + 2); // "532"
console.log(3 + 2 + "5"); // "55"
console.log(true + 1);    // 2
console.log("abc" - 1);   // NaN

+ has two jobs — adding numbers and joining strings. If either side is a string, it joins. Every other maths operator — - * / % — only knows how to do maths, so it converts the string to a number first.

Read left to right: "5" + 3 + 2 → "53" + 2 → "532". But 3 + 2 + "5" → 5 + "5" → "55". The same three values, a different order, a different answer.
This is the bug in real forms: two quantity inputs, qty1.value + qty2.value, and the total of 2 and 3 comes out as "23". The fix is always the same — Number() both sides before you add.
Part 2 · Truthy and falsy

Only eight values are falsy. Learn the list.

An if does not need a true or false. It accepts any value and asks "does this count as true?" These eight count as false. Everything else — every other value in the language — counts as true.

false0-00n""nullundefinedNaN
live · edit and run
// Boolean(x) asks: would an if() treat x as true?
console.log(Boolean(0));        // false
console.log(Boolean(""));       // false
console.log(Boolean(NaN));      // false
console.log(Boolean(null));     // false

console.log(Boolean("0"));      // true  — a non-empty string
console.log(Boolean("false"));  // true  — still just text
console.log(Boolean(" "));      // true  — a space is a character
console.log(Boolean([]));       // true  — an empty list still exists
"0""false"" "[ ]{ }-1

All of these are truthy. The string "0" is not the number 0 — it is a one-character string, and every non-empty string is truthy. An empty array is still an array that exists.

Why it matters: if (cart) is true even when the cart array is empty. To check for "no items", test cart.length === 0 — say exactly what you mean.
Part 2 · Logical operators

&&, || and ?? — and the default-value trap

a && b
AND — true only if both are true. Stops at the first falsy value.
a || b
OR — true if either is true. Stops at the first truthy value.
!a
NOT — flips it. !!a turns any value into a true boolean.
a ?? b
Use b only if a is null or undefined.
a?.b
Read b only if a exists — no crash if it does not.
The trap: || treats 0 and "" as "missing", because they are falsy. So a quantity of 0 becomes your default of 10 — a real bug in real carts. ?? only replaces null and undefined, which is almost always what you meant.
live · edit and run
const age = 21, hasId = true;
console.log(age >= 18 && hasId);   // true

const qty = 0;
console.log(qty || 10);            // 10 — WRONG, 0 was real
console.log(qty ?? 10);            // 0  — correct

const nickname = null;
console.log(nickname ?? "Guest"); // "Guest"

const user = null;
console.log(user?.name);           // undefined, no crash
Part 3 · Decisions

if, else if, else — and why the order matters

live · edit and run
const marks = 82;   // edit this and run again

if (marks < 0 || marks > 100) {
  console.log("Invalid marks");
} else if (marks >= 90) {
  console.log("Grade A");
} else if (marks >= 75) {
  console.log("Grade B");
} else if (marks >= 60) {
  console.log("Grade C");
} else if (marks >= 40) {
  console.log("Grade D");
} else {
  console.log("Grade F");
}
  • JavaScript checks each condition top to bottom and stops at the first true one. Nothing below it is even looked at.
  • So the order is part of the logic. Put marks >= 40 first and a score of 95 prints "Grade D" — the first condition that matched.
  • Check the invalid cases first. Throw out the impossible inputs before you start reasoning about the normal ones — this is called a guard, and it keeps the rest of the logic simple.
Try this live: press Edit, set marks to 90, then 89, then 101, then -5. Boundaries are exactly where placement tests put their hidden test cases.
Part 3 · Decisions

The ternary and switch — and the switch trap

Ternary — an if/else that produces a value
live · edit and run
const age = 17;
const status = age >= 18 ? "adult" : "minor";
console.log(status);

// condition ? value-if-true : value-if-false
const seats = 1;
console.log(`${seats} seat${seats === 1 ? "" : "s"} left`);

Use it to choose a value. Do not nest ternaries inside ternaries — use an if/else instead.

switch — one value compared against many
live · edit and run
const day = "sat";

switch (day) {
  case "sat":
  case "sun":
    console.log("Weekend — no session");
    break;
  case "fri":
    console.log("Weekly task due");
    break;          // delete this line and run again
  default:
    console.log("Session at 10 am");
}
The switch trap: without break, execution falls through into the next case and runs that too. Delete the break after the "fri" case, set day to "fri", and run it — you get two lines. Sometimes you want that (sat and sun share one body above); usually it is a bug. And switch compares with ===, so "1" never matches case 1.
Part 3 · Loops

The for loop has three parts, and they run in a fixed order

live · edit and run
let total = 0;

for (let i = 1; i <= 5; i++) {
  total += i;
  console.log(`i = ${i}   total = ${total}`);
}

console.log("final total:", total);

Run it and read the output as a trace table — one row per round, showing every variable. When a loop gives the wrong answer, writing this table by hand is the single fastest way to find out why.

Off-by-one is the classic loop bug. i < 5 runs four times starting from 1; i <= 5 runs five. Before you run any loop, say out loud: what is the first value, what is the last value, how many rounds?
Part 3 · Loops

while — when you do not know how many rounds

How many times can you halve 100 before it drops below 1?
live · edit and run
let value = 100;
let steps = 0;

while (value >= 1) {
  value = value / 2;
  steps++;
}

console.log(`${steps} halvings`);

A for loop is for "do this n times". A while loop is for "keep going until something is true" — you cannot know the count in advance.

Break it on purpose — this loop never ends
live · edit and run
let i = 10;

while (i > 0) {
  console.log(i);
  i++;   // should be i-- … nothing ever reaches 0
}
Run it. In a normal page this freezes the tab. The runner stops it after a second and a half and tells you why. Every loop must change something its condition depends on — otherwise the condition can never become false.
Part 3 · Loops

Just enough about arrays to loop over one

An array is an ordered list of values. You will study arrays properly in the next module — this is the minimum you need so loops have something to walk through.

live · edit and run
const cities = ["Indore", "Bhopal", "Pune"];

console.log(cities.length);   // 3
console.log(cities[0]);       // counted from 0
cities.push("Nagpur");        // add to the end
console.log(cities);

// the classic loop, by position
for (let i = 0; i < cities.length; i++) {
  console.log(i, cities[i]);
}

// for…of — when you only need the values
for (const city of cities) {
  console.log(city.toUpperCase());
}
  • Positions start at 0, so the last item is always at length - 1. That is why the loop is i < cities.length and not <=.
  • for…of hands you each value in turn — no counter, no off-by-one. Reach for it whenever you do not need the position.
  • const cities and then push is allowed: const stops you swapping the whole list for another one, not changing what is in it.
Avoid for…in on arrays. It walks the keys as strings — "0", "1" — not the values, and it can pick up extra properties. It is for objects, and even there there are better tools.
Part 3 · Loops

break stops the loop. continue skips one round.

break — stop as soon as you find it
live · edit and run
const marks = [45, 72, 38, 91, 60];

for (const m of marks) {
  if (m < 40) {
    console.log(`Found a fail: ${m}`);
    break;       // no need to look further
  }
  console.log(`checked ${m}`);
}
continue — skip this one, carry on
live · edit and run
const marks = [45, 72, 38, 91, 60];
let passTotal = 0;

for (const m of marks) {
  if (m < 40) continue;   // skip fails
  passTotal += m;
}

console.log("sum of passes:", passTotal);
Where this shows up: searching (stop at the first match with break) and filtering (skip what you do not want with continue). Both make a loop faster and easier to read — the intent is written on the line where it happens.
Part 4 · Functions

A function is a named, reusable step

live · edit and run
function area(width, height) {
  return width * height;
}

// the values passed in are called ARGUMENTS
console.log(area(4, 5));
console.log(area(10, 2));

const room = area(3.5, 4);
console.log(`Room: ${room} sq m`);
  • Parameter — the name in the definition (width). Argument — the actual value you pass in (4). Interviewers do ask the difference.
  • Write it once, use it everywhere. If you find yourself copying the same three lines, they want to be a function.
  • A good function does one thing, and its name says what. If you need the word "and" to name it, it is two functions.
Part 4 · Functions

Three ways to write the same function

live · edit and run
// 1. declaration
function double(n) {
  return n * 2;
}

// 2. expression — a function stored in a const
const triple = function (n) {
  return n * 3;
};

// 3. arrow — the modern short form
const square = (n) => n * n;

console.log(double(5), triple(5), square(5));
FormUse it for
declarationNamed, top-level functions — the main steps of your program
arrowShort functions, and the ones you pass to other functions — you will do this constantly with arrays and in React
expressionMostly reading older code
Arrow shorthand: with one expression and no braces, the value is returned automatically — (n) => n * n. The moment you add { }, you must write return yourself, or you get undefined.
Part 4 · Functions

return is not console.log

This is the single most common beginner mistake, and every placement test catches it. console.log shows a value to a human. return hands a value back to the code that called the function. They look similar on screen and do completely different jobs.

prints the answer — returns nothing
live · edit and run
function addPrint(a, b) {
  console.log(a + b);
}

const result = addPrint(2, 3);
console.log("result is", result);
console.log(result * 10);
returns the answer — the caller can use it
live · edit and run
function addReturn(a, b) {
  return a + b;
}

const result = addReturn(2, 3);
console.log("result is", result);
console.log(result * 10);
Why placement tests catch it: the grader calls your function and checks what comes back. It never looks at what you printed. A function that prints the perfect answer and returns nothing scores zero on every test case. The lab for this module detects exactly this mistake and tells you when you have made it.
Part 4 · Scope

Scope — which variables can this line see?

Inner code can see outward. Outer code can never see inward. The function cannot see discount; the global code cannot see tax.

live · edit and run
const TAX = 0.18;

function bill(price) {
  const tax = price * TAX;       // sees TAX: outward is fine
  if (price > 1000) {
    const discount = 50;
    return price + tax - discount;
  }
  return price + tax;
}

console.log(bill(2000));
console.log(bill(500));
console.log(tax);                // outer can't see inner
let and const live inside the nearest { } — a function, an if, a loop. That is called block scope, and it is why a loop's let i does not leak out after the loop ends. Keeping variables in the smallest scope that works is how large programs stay understandable.
Part 4 · Habits

Four habits that make code pass tests — and code review

live · edit and run
// 1. default parameters
function greet(name = "Guest") {
  return `Welcome, ${name}`;
}
console.log(greet("Asha"));
console.log(greet());

// 2. guard clause: reject bad input first, return early
function percent(part, whole) {
  if (whole === 0) return 0;
  return Math.round((part / whole) * 100);
}
console.log(percent(38, 50));
console.log(percent(5, 0));

// 3. pure: same input, same output, changes nothing else
const withGst = (amount) => amount * 1.18;
console.log(withGst(100), withGst(100));
  • Default parameters handle a missing argument without an if. Note they only apply to undefined — pass "" and the default does not kick in.
  • Guard clauses deal with the edge cases at the top and return immediately. The rest of the function can then assume the input is sensible — no deep nesting.
  • Pure functions depend only on their parameters and change nothing outside. They are trivial to test, which is exactly why test-based interviews are built from them.
  • 4 · Name it like an instruction. calculateTotal, isValidEmail, formatPrice. You should know what it returns without reading the body.

What to carry out of this module

  • const by default, let when it changes, never var.
  • Always ===. Convert types on purpose with Number() and String(), never by accident.
  • + joins if either side is a string. Values from forms are always strings.
  • Eight falsy values. Everything else — including "0" and [] — is truthy.
  • ?? for defaults, not ||, whenever 0 or an empty string is a real answer.
  • Order your if/else from the edge cases in. The first true condition wins.
  • Every loop must change what its condition checks, or it never ends.
  • Say the first value, the last value and the count before you run any loop.
  • return hands back. console.log only shows. Tests read what you return.
  • Inner scope sees outward, never inward.
