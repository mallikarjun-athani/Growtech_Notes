Module 03

CSS properties · the box model · shorthandEverything is a box

CSS has more than five hundred properties. You will use about sixty of them every day for the rest of your career. This module covers those sixty, then the single model that explains why every layout you have ever fought with behaved the way it did.

Family 01 · Text

Six properties do ninety percent of typography

font-family
The typeface, with fallbacks — always end the list with a generic family.
font-size
Use rem, not px, so the user's browser setting still works.
font-weight
400 normal, 600 semibold, 700 bold. Numbers, not bolder.
line-height
Unitless. 1.5 for body, 1.1 for headings. A unit here breaks inheritance.
color
The text colour. Note the American spelling — there is no colour.
text-align
left, center, right. Never justify on the web — it creates rivers.
The line-height trap: line-height: 24px inherits the literal 24px into children, no matter how small their text becomes. line-height: 1.5 inherits the ratio. Always use the ratio.
A type scale that looks designed
  • 3rem / 1.05Display
  • 2rem / 1.1Heading 1
  • 1.5rem / 1.2Heading 2
  • 1.125rem / 1.4Lead paragraph
  • 1rem / 1.6Body text sits here
  • 0.875rem / 1.5Caption and small print

Each step is roughly 1.25× the one below it. Pick a ratio once, and every heading in the product lines up for free.

Family 01 · Text

The polish layer

letter-spacing

Tighten big headings

Open up small caps

Negative on large type, positive on small uppercase. Never on body text.

text-transform

uppercase

capitalize each word

Changes appearance only. The underlying text stays as typed — which is what a screen reader and a copy-paste get.

text-decoration

underline with offset

line-through

Use text-underline-offset to stop the line cutting through descenders.

white-space 
white-space: nowrap;

Stops text wrapping. The usual cause of a table column that will not behave.

text-overflow
This sentence is deliberately far too long to fit in this card

Needs all three: overflow:hidden, white-space:nowrap, text-overflow:ellipsis. One alone does nothing.

text-wrap

A headline that balances its lines instead of leaving one orphan word

balance on headings, pretty on paragraphs. Two words that make typography look professional.

Ask the room: why does text-overflow: ellipsis so often "not work"? Because it only applies to content that is actually overflowing on one line — without nowrap the text simply wraps instead, and nothing ever overflows.

The one that replaced media queries 
font-size: clamp(1.5rem, 4vw, 3rem);

Never smaller than 1.5rem, never larger than 3rem, fluid in between. One line replaces three breakpoints.

The em trap, in numbers 
.a { font-size: 1.2em }  /* 19.2px */
.a .a { /* inherits, then × 1.2 → 23px */ }
.a .a .a { /* → 27.6px */ }

Three levels of nesting and your "1.2em" is now 27.6px. rem never compounds.

Family 02 · Colour

Four ways to write the same colour

Hex#0E6E68
Compact. Unreadable.
RGBrgb(14 110 104)
Additive light. Still unreadable.
HSLhsl(177 77% 24%)
Hue, saturation, lightness.
Alphahsl(… / .45)
Transparency on any notation.

Why HSL is the one to teach

Keep the hue, change the lightness, and you have a whole palette that matches — no design tool required.

92%
74%
50%
32%
18%

One hue. One saturation. Five lightness values. That is a usable palette in thirty seconds.

What the industry actually ships

/* define once, at the root */
:root {
  --brand: hsl(177 77% 24%);
  --ink:   hsl(200 22% 9%);
  --line:  hsl(195 15% 88%);
}

/* use everywhere */
.button { background: var(--brand) }
This is not advanced. Custom properties are how every real codebase handles colour. Change one line at the root and the entire product rebrands.
Family 02 · Colour

Backgrounds — one property, seven jobs

background-color

A flat colour. Paints the padding box, not just behind the text.

linear-gradient

A gradient is an image, not a colour — so it goes in background-image.

background-size: cover

cover fills and crops. contain fits and letterboxes. The difference is the whole job.

The shorthand, unpacked 
.hero {
  background: #0E6E68 url(hero.jpg) center / cover no-repeat;
}

/* is exactly the same as */
.hero {
  background-color:    #0E6E68;
  background-image:    url(hero.jpg);
  background-position: center;
  background-size:     cover;
  background-repeat:   no-repeat;
}
  • The slash is mandatory. Size can only appear immediately after position, separated by /. Anywhere else it is ignored.
  • Set a background-color too. It shows while the image loads, and if the image 404s the text is still readable.
  • Decorative images belong in CSS. Content images belong in <img> with an alt. If it carries meaning, it is not a background.
Interview answer worth having: background is a shorthand, so writing it resets every background-* property you did not mention — including a background-image set earlier in the cascade.
Family 04 · Border

Borders, radius, shadow — and the one that is not a border

border

width style color. Miss out style and nothing renders — the default is none.

border-radius

50% gives a circle on a square. 999px gives a pill on any rectangle.

box-shadow

Two shadows — one tight, one wide — read as real depth. One big blurry shadow reads as a smudge.

outline

Drawn outside the border and takes up no space. This is why it is the focus ring.

Never do this 
*:focus { outline: none; }

You have just made the product unusable for every keyboard user — and it is the single most common accessibility failure in the industry.

Do this instead 
:focus-visible {
  outline: 3px solid var(--brand);
  outline-offset: 2px;
}

:focus-visible shows the ring for keyboard users and hides it for mouse clicks. You get a clean design and an accessible one.

Family 05 · Display

display decides the rules everything else plays by

ValueSitsRespects width / height?Vertical margin?Typical use

inlineIn the flow of textNoNospan, a, strong, em
inline-blockIn the flow, but is a boxYesYesButtons and chips in a sentence

The bug you will hit this week 
a { width: 200px; padding: 20px 0; }

Neither line works. An <a> is inline: width is ignored, and vertical padding overflows the line box without pushing anything apart. Add display:inline-block and both start working.

Three ways to hide — they are not the same
display:none
Gone. No space, not in the accessibility tree, not read aloud.
visibility:hidden
Invisible but still occupies its space. The gap stays.
opacity:0
Invisible, occupies space, and is still clickable. The classic phantom-button bug.
Family 06 · Position

position — five values, one question each

The question that catches everyone: "absolute to what?" — to the nearest ancestor whose position is anything other than static. If there isn't one, it goes all the way up to the page. This is why position:relative on a parent, with no offsets at all, is one of the most-written lines in CSS.
Families 07 & 08

Overflow, motion, and the pointer

overflow — what happens when it does not fit

visible
The default. Content spills out and is still visible.
hidden
Clipped. Also the fix for a child escaping a rounded corner.
auto
A scrollbar appears only when needed. Almost always the right answer.
scroll
A scrollbar always, even when it is not needed.
overflow-x
Wrap a wide table in a container with overflow-x:auto — the page stops scrolling sideways on phones.
Debug trick worth memorising: when a page scrolls sideways on mobile and you cannot find why, add * { outline: 1px solid red } and the guilty element shows itself immediately.

transition — four values, in order

transition: background-color .2s ease 0s;
              /*  what   how long  curve  delay */

Hover both — only one of them eases.

  • Never animate all. It transitions properties you did not intend and costs performance. Name them.
  • Only transform and opacity are cheap. Animating width, top or margin forces the browser to redo layout on every frame.
  • cursor:pointer is a hint, not a feature. If it needs a pointer cursor to look clickable, it should probably have been a <button>.

Part 2 · The box model

Every element on every page is four nested rectangles

The rule that explains most confusion: width measures the content box only by default. Padding and border are added on top of it, not contained within it.
Why margin has no colour: margin is not part of the element. It is a request for empty space next to it — so there is nothing there to paint. Set a background and you will see it stop at the border.
Part 2 · The box model

The arithmetic that surprises everyone

You asked for a box 300 pixels wide. Measure it on the page and it is 350. Nothing is broken — this is the default box model doing exactly what it was designed to do.

.card {
  width:   300px;
  padding: 20px;
  border:  5px solid;
}
300+ 20+ 20+ 5+ 5
= 350px on screen

Content 300. Padding twice — left and right. Border twice — left and right. Margin is not counted here because margin is outside the box, not part of it.

Where this bites in real work: four cards at width:25% with any padding at all will not fit on one row — they add up to more than 100%. The whole industry hit this so often that the fix became a universal default.
Part 2 · The box model

box-sizing: the one line every project starts with

content-box · the default

width = content only

width: 300px;  /* content */
padding: 20px;
border: 5px solid;
/* → renders 350px wide */
content-box

You asked for 300. You got 350. Every calculation you do must now account for padding you may not even have written.

border-box · what you want

width = the whole visible box

box-sizing: border-box;
width: 300px;  /* total */
padding: 20px;
border: 5px solid;
/* → renders 300px wide */
border-box

Padding and border now grow inwards. The content shrinks to 250px and the box stays at 300, exactly as asked.

Put this at the top of every stylesheet you ever write 
*, *::before, *::after {
  box-sizing: border-box;
}
Worth saying out loud: this is not a workaround or a hack. Every CSS framework in existence ships this line. The original model was a specification decision from 1996 that the industry quietly voted against — and box-sizing is the vote.
Part 2 · The box model

Margin is the odd one out

Difference 1

It is outside

Padding is inside the border and takes the background colour. Margin is outside it and is always transparent, whatever you set.

Difference 2

It can be negative

margin-top: -20px pulls the element upward and overlaps what is above it. padding: -20px is simply invalid and ignored.

Difference 3

It collapses

Two vertical margins meeting each other do not add up. The larger one wins and the smaller disappears. Padding never does this.

Padding or margin? One question decides it.

Should the background stretch to cover this space?
Yes → padding.   No → margin.
padding
colour reaches the edge
margin
colour stops at the border

margin: auto — the centring rule

.page {
  max-width: 1100px;
  margin: 0 auto;   /* ← centred */
}
  • Horizontal only. margin: auto 0 does not centre vertically — auto resolves to zero on the vertical axis.
  • The element must have a width. A block element with no width already fills its parent, so there is no free space for auto to split.
  • For vertical centring use flexbox: display:flex; align-items:center. That is what it is for.
Part 2 · The box model

Margin collapse — three rules, and the bug it causes

Rule 1 · Adjacent siblings

Two elements stacked on top of each other. The bottom margin of the first and the top margin of the second merge into one.

Rule 2 · Parent and first child

A parent with no padding or border "leaks" its child's top margin outside itself. The child moves nothing — the parent moves down.

Rule 3 · Empty elements

An element with no content, padding or border collapses its own top and bottom margins into each other.

The three ways to stop it: add padding or a border to the parent · give the parent display:flex or grid · use gap instead of margins altogether. In modern work, the answer is almost always gap — it never collapses, never leaks, and applies only between items.
Part 3 · Shorthand

The clock rule

Four values go clockwise from the top: top, right, bottom, left. Give fewer, and the missing sides copy the side opposite them. This one rule covers margin, padding, border-width, border-color, border-style and inset.

padding: 10px
1 value → all four sides
padding: 10px 30px
2 values → vertical, horizontal
padding: 10px 30px 40px
3 values → top, sides, bottom
padding: 10px 30px 40px 5px
4 values → T, R, B, L clockwise
The memory hook that actually sticks: start at twelve o'clock and go clockwise — T R B L. Say it as "trouble". Then: three values means the left side copies the right, and two values means each side copies its opposite.

The border-radius detail nobody teaches 
border-radius: 12px 12px 0 0;
/* TL  TR  BR  BL — corners, not sides */

Corners start at top-left and go clockwise, exactly like the sides do. This is how you round only the top of a card header.

flex: 1 is three values in disguise 
flex: 1;
/* means: flex: 1 1 0% */
/* grow yes · shrink yes · start from 0 */

This is why flex:1 makes every child the same width regardless of its content — the basis is zero, so only the growth factor matters.

Part 3 · Shorthand

The shorthand trap — it resets what you left out

A shorthand does not set only the values you wrote. It sets every property in the family, and anything you omitted is reset to its initial value — silently.

The bug 
.card {
  background-image: url(pattern.png);
  background-color: navy;
}

.card.featured {
  background: gold;   /* ← shorthand */
}

The pattern image is gone. Writing the background shorthand reset background-image back to none, even though the line never mentions images.

The fix 
.card.featured {
  background-color: gold;
}

Use the longhand when you are overriding one thing. Use the shorthand when you are declaring the whole family from scratch.

The working rule: shorthand to set, longhand to override.
Same trap, different property 
h1 { font-weight: 800; }
h1 { font: 2rem system-ui; }
/* weight is now 400 — the shorthand reset it */
And the one that costs an afternoon 
transition: color .2s;
transition: background .3s;
/* colour no longer transitions at all */
/* correct: transition: color .2s, background .3s */

What to carry out of this module

  • Name the family before you name the property. Eight questions cover five hundred properties.
  • rem for size, px for hairlines. em only where compounding is the point.
  • width measures content, not the box — until you write box-sizing: border-box, which you should write once, at the top, for everything.
  • Padding if the background should stretch. Margin if it should not. One question, every time.
  • Vertical margins collapse. gap does not. In flex and grid layouts, reach for gap first.
  • Four values go clockwise from the top. Fewer values, and each side copies its opposite.
  • border without a style renders nothing. The initial value of border-style is none.
  • Shorthand to set, longhand to override. A shorthand silently resets everything you did not write.
  • Never remove the focus outline. Restyle it with :focus-visible instead.
  • Only transform and opacity animate cheaply. Everything else redoes layout on every frame.
