Every screen you will build takes a list of records and turns it into something a person can read — a job board, a cart, a dashboard. This module is about that one skill: picking, reshaping and summarising data, the way it is done in real code.

Why this module

Real data is an array of objects

This is what an API sends back. Not one value — a list, where every item is a record with named fields. Every screen asks the same three questions of it.

The MERN connection: MongoDB returns arrays of objects. Express sends them as JSON. React turns each one into a card with map. The language changes between layers; the data shape does not.
Part 1 · Arrays

An array is an ordered list, counted from zero

live · edit and run
const cities = ["Indore", "Pune", "Bhopal", "Nagpur"];

console.log(cities[0]);          // first
console.log(cities.length);      // how many
console.log(cities[cities.length - 1]);  // last, the old way
console.log(cities.at(-1));      // last, the modern way
console.log(cities[10]);         // past the end — no error!

console.log(typeof cities);          // surprise
console.log(Array.isArray(cities));  // the real test
  • Index 0 is the first item. The last is always at length - 1.
  • Reading past the end gives undefined, not an error. That silence is where many bugs start — the code keeps running with nothing.
  • at(-1) counts from the end. at(-2) is second-last. Square brackets cannot do that: cities[-1] is undefined.
  • typeof says "object" for an array. Use Array.isArray() whenever you need to know.
Ask the room: const list = []; — is if (list) true or false? It is true. An empty array is still an object, and every object is truthy. Check list.length === 0 instead.
Part 1 · Arrays

The first question to ask of any method: does it change the original?

Changes the original array

Mutating methods

pushpopshiftunshiftsplicesortreversefill

The array you passed in is different afterwards. Anyone else holding it sees the change.

Returns something new

Non-mutating methods

mapfilterreducesliceconcatflatjointoSortedtoReversedwith

The original is untouched. You get a fresh array or value back.

live · edit and run
const scores = [70, 95, 82];
const sorted = scores.sort((a, b) => a - b);

console.log(sorted);             // [70, 82, 95] — fine
console.log(scores);             // …but the original moved too
console.log(sorted === scores);  // it is the SAME array

const safe = [40, 10, 30];
const copy = safe.toSorted((a, b) => a - b);
console.log(safe, copy);         // original kept
Why this matters for placement: React re-renders only when it sees a new array. Mutate the old one with push or sort and the screen silently does not update. The single most common React bug in a fresher's first month starts right here.

Part 1 · Arrays

slice versus splice — the pair everyone mixes up

slice(start, end) · copies

A slice of cake — the cake is still there

Returns the items from start up to but not including end. Negative numbers count from the end. The original never changes.

splice(start, deleteCount, …items) · edits

Splicing film — you cut the actual reel

Removes deleteCount items from start, optionally inserts new ones there, and returns what it removed. The original is changed.

live · edit and run
const menu = ["poha", "jalebi", "samosa", "kachori", "chai"];

console.log(menu.slice(1, 3));   // copy items 1 and 2
console.log(menu.slice(-2));     // the last two
console.log(menu);               // untouched

const removed = menu.splice(1, 2);        // cut two out
console.log(removed, menu);

menu.splice(1, 0, "bhutte ka kees");      // insert, remove nothing
console.log(menu);

Part 1 · Arrays

Sorting properly

live · edit and run
console.log([10, 1, 3, 25].sort());          // surprise
console.log([10, 1, 3, 25].sort((a, b) => a - b));  // low → high
console.log([10, 1, 3, 25].sort((a, b) => b - a));  // high → low

const jobs = [
  { company: "Orbit",   lpa: 7.5 },
  { company: "Kestrel", lpa: 4.5 },
  { company: "Nimbus",  lpa: 6   },
];
const byPay = jobs.toSorted((a, b) => b.lpa - a.lpa);
console.log(byPay.map(j => j.company));

const names = ["ravi", "Asha", "imran", "Zoya"];
console.log(names.toSorted());      // capitals first?!
console.log(names.toSorted((a, b) => a.localeCompare(b)));
  • With no comparator, sort compares as text. "10" comes before "3" because "1" comes before "3". That is why numbers come out wrong.
  • The comparator returns a number: negative puts a first, positive puts b first. a - b is ascending; b - a is descending.
  • For text, use localeCompare — plain sort puts every capital letter before every lowercase one.
  • sort changes the original. Use toSorted, or copy first: [...jobs].sort(…).

Part 2 · map, filter, reduce

map — one in, one out, new shape

live · edit and run
const jobs = [
  { company: "Nimbus Labs",   city: "Pune",   lpa: 6 },
  { company: "Kestrel Tech",  city: "Indore", lpa: 4.5 },
  { company: "Orbit Systems", city: "Pune",   lpa: 7.5 },
];

const names = jobs.map(job => job.company);
console.log(names);

const labels = jobs.map(job => `${job.company} · ${job.city}`);
console.log(labels);

const cards = jobs.map((job, i) => ({
  rank: i + 1,
  title: job.company,
}));
console.log(cards);

// the classic mistake — braces without return
console.log(jobs.map(job => { job.company }));
  • map calls your function once per item and collects whatever it returns into a new array.
  • Same length in, same length out. If you want fewer items, that is filter's job.
  • Arrow with braces needs return. job => { job.company } returns nothing — you get an array of undefined.
  • Returning an object? Wrap it in brackets: job => ({ … }). Without them, JavaScript reads the braces as a function body.
In React this exact line renders a list: jobs.map(job => <JobCard key={job.id} … />). Master map now and that syntax will feel obvious.

filter — keep the ones that pass

live · edit and run
const jobs = [
  { company: "Nimbus", city: "Pune", lpa: 6, remote: true },
  { company: "Kestrel", city: "Indore", lpa: 4.5, remote: false },
  { company: "Orbit", city: "Pune", lpa: 7.5, remote: false },
  { company: "Saffron", city: "Indore", lpa: 4, remote: true },
];

const remote = jobs.filter(job => job.remote);
console.log(remote.length, "remote jobs");

const wellPaid = jobs.filter(job => job.lpa >= 6);
console.log(wellPaid.map(job => job.company));

const puneOnsite = jobs.filter(
  job => job.city === "Pune" && !job.remote
);
console.log(puneOnsite.map(job => job.company));

console.log(jobs.filter(job => job.city === "Delhi")); // none

console.log([0, "", "Asha", null, 42, undefined].filter(Boolean));
  • Your function answers yes or no for each item. The yeses are kept, in their original order.
  • It always returns an array — possibly empty. Never undefined, never a single item. For one item, use find.
  • Combine conditions with && and || inside one filter rather than chaining three.
  • filter(Boolean) is the idiom for "drop every empty value" — each item is passed to Boolean, and falsy ones fail.

Part 2 · map, filter, reduce

reduce can build an object: counting and grouping

live · edit and run
const jobs = [
  { company: "Nimbus Labs",   city: "Pune"   },
  { company: "Kestrel Tech",  city: "Indore" },
  { company: "Orbit Systems", city: "Pune"   },
  { company: "Saffron Soft",  city: "Indore" },
  { company: "Vyom Data",     city: "Bhopal" },
];

// COUNT — how many jobs in each city?
const perCity = jobs.reduce((acc, job) => {
  acc[job.city] = (acc[job.city] || 0) + 1;
  return acc;
}, {});
console.log(perCity);

// GROUP — which companies are in each city?
const byCity = jobs.reduce((acc, job) => {
  (acc[job.city] ??= []).push(job.company);
  return acc;
}, {});
console.log(byCity);
  • Start with {} and the accumulator is an object you fill in as you go.
  • Bracket notation acc[job.city] uses the city's value as the key. acc.city would create one key literally called "city" — the most common mistake here.
  • Always return acc. Forget it and the next step receives undefined.
  • One shape, two jobs: start empty, work out the key, update the value, return the accumulator. Counting adds one; grouping pushes into a list.
Part 2 · map, filter, reduce

A lookup table joins two lists

live · edit and run
const users = [
  { id: 7, name: "Asha" },
  { id: 9, name: "Ravi" },
];
const orders = [
  { orderId: "A1", userId: 9, total: 450 },
  { orderId: "A2", userId: 7, total: 120 },
  { orderId: "A3", userId: 9, total: 300 },
];

// build the lookup ONCE: id → user
const usersById = Object.fromEntries(users.map(u => [u.id, u]));
console.log(usersById);

// every order now finds its user in one step
const rows = orders.map(o =>
  `${o.orderId}: ${usersById[o.userId].name} paid ₹${o.total}`);
console.log(rows);
  • Real data arrives in pieces. An orders API gives you userId: 9, not a name. The screen needs the name.
  • Build an object keyed by id, once — with reduce, or Object.fromEntries(list.map(x => [x.id, x])). After that, usersById[9] is instant.
  • The slow way is users.find(u => u.id === o.userId) inside the map — a fresh search for every single order.
This is a join. SQL does it with JOIN; MongoDB does it with $lookup or populate(). When the data is already in JavaScript, a lookup table is how you do it yourself.

Part 2 · map, filter, reduce

Write your own map and filter — the interview question

live · edit and run
function myMap(arr, fn) {
  const out = [];
  for (let i = 0; i < arr.length; i++) {
    out.push(fn(arr[i], i, arr));   // item, index, the array
  }
  return out;                       // a NEW array
}

function myFilter(arr, test) {
  const out = [];
  for (let i = 0; i < arr.length; i++) {
    if (test(arr[i], i, arr)) out.push(arr[i]);
  }
  return out;
}

const nums = [5, 12, 8, 20];
console.log(myMap(nums, n => n * 10));
console.log(myMap(nums, (n, i) => `${i}:${n}`));
console.log(myFilter(nums, n => n > 9));
console.log(nums);                  // untouched

"Write your own map" is asked in fresher interviews because it proves you know what the method does, not just how to call it. Each one is a loop you already know.

  • It returns a new array and never touches the one it was given.
  • The callback gets three arguments — the item, its index, and the whole array — which is why (n, i) => … works on the real one too.
  • filter is the same loop, pushing the item only when the test says yes.
Say these out loud while you type. The interviewer is listening for "new array" and "index as the second argument" more than for the loop itself.
Part 2 · map, filter, reduce

Write your own reduce — the edge cases are the question

live · edit and run
function myReduce(arr, fn, initial) {
  let i = 0;
  let acc = initial;
  if (arguments.length < 3) {        // no starting value?
    if (arr.length === 0) {
      throw new TypeError("Reduce of empty array");
    }
    acc = arr[0];                    // first item is the start
    i = 1;                           // …so begin at the second
  }
  for (; i < arr.length; i++) {
    acc = fn(acc, arr[i], i, arr);
  }
  return acc;
}

const add = (s, n) => s + n;
console.log(myReduce([1, 2, 3, 4], add, 0));  // start 0
console.log(myReduce([1, 2, 3, 4], add));     // no start
console.log(myReduce([], add, 100));          // empty, start 100
console.log(myReduce([], add));               // empty, no start
  • With a starting value, the callback runs once for every item.
  • Without one, the first item is the start, and the callback begins at the second item — it runs one time fewer.
  • An empty array with a start simply returns the start. Without one, there is nothing to return, so it throws a TypeError.
  • Why arguments.length, not initial === undefined? Because someone might pass undefined on purpose as a real starting value.
This is the follow-up that separates candidates: "what happens with an empty array?" Most people have never thought about it. Now you have.

An object is a record: named fields, not positions

live · edit and run
const job = { company: "Nimbus Labs", city: "Pune", lpa: 6 };

console.log(job.company);   // dot — name written in code
const field = "city";
console.log(job[field]);    // brackets — name in a variable

job.remote = true;             // add a field
job.lpa = 6.5;                 // change one
delete job.city;               // remove one

const company = "Orbit", key = "lpa";

  • Dot notation when the field name is written in your code. Brackets when it comes from a variable or a loop, or contains a space or dash.

  • Computed keys { [key]: value } use a variable as the field name — handy for forms, where the input's name decides which field to update.

Looping over an object: keys, values, entries

Objects have no map or filter. The trick is to turn the object into an array, use the array methods, then turn it back.

{ html: 2000, … }Object.entries →[["html", 2000], …].map / .filter →[["html", 2200], …]Object.fromEntries →{ html: 2200, … }

const fees = { html: 2000, css: 2500, react: 6000, node: 5500 };

console.log(Object.keys(fees));
console.log(Object.values(fees));

console.log(Object.values(fees).reduce((a, b) => a + b, 0)); // sum

// raise every fee by 10% — rounded, because in floating
// point 6000 * 1.1 is 6600.000000000001

Destructuring — unpack in one line

live · edit and run
const job = { company: "Orbit Systems", city: "Pune", lpa: 7.5 };

const { company, lpa } = job;           // pull fields out
const { city: location } = job;         // rename
const { remote = false } = job;         // default if missing
const { company: name, ...rest } = job; // gather the rest
console.log(company, lpa, location, remote, rest);

const [first, , third] = ["Asha", "Ravi", "Neha"]; // skip one
console.log(first, third);

let a = 1, b = 2;
[a, b] = [b, a];                        // swap
console.log(a, b);

// exactly how React props arrive:
function card({ company, lpa = 0 }) {
  return `${company}: ${lpa} LPA`;
}
console.log(card(job));
  • Objects destructure by name; arrays by position. An empty slot between commas skips one.
  • { city: location } reads city and stores it as location. The colon means "rename", not "type".
  • Defaults apply only to undefined. A field that is null keeps its null.
  • Destructuring undefined crashes, the same as reading a field of it.
You will read this constantly: const { data } = await axios.get(url), function Card({ title, price }), const [count, setCount] = useState(0). All three are destructuring.

Spread — copy, merge, combine

live · edit and run
const frontend = ["HTML", "CSS"];
const backend = ["Node", "Express"];
const stack = [...frontend, "React", ...backend];
console.log(stack);

const defaults = { theme: "light", pageSize: 10, lang: "en" };
const saved    = { theme: "dark", pageSize: 25 };
const settings = { ...defaults, ...saved };   // later wins
console.log(settings);

const job = { company: "Nimbus", lpa: 6 };
const updated = { ...job, lpa: 6.5 };    // copy, one change
console.log(job, updated);

function total(...prices) {              // rest: gather
  return prices.reduce((sum, p) => sum + p, 0);
}
console.log(total(120, 80, 45));
console.log(Math.max(...[4.5, 7.5, 6])); // spread: expand
  • The same three dots do two opposite jobs. In an array or object literal, or a function call, they spread things out. In a parameter list or destructuring, they gather the rest up.
  • When keys clash, the later one wins. That makes { ...defaults, ...saved } the standard way to apply user settings over defaults.
  • { ...job, lpa: 6.5 } is the everyday "copy with one change" — the building block of every state update in React.
But: spread copies one level. The next slide shows what happens to anything nested inside.

Silently ignored is the dangerous part. Outside strict mode, writing to a frozen object does nothing and says nothing. Inside strict mode — which every ES module and every class is — it throws a TypeError, which is what you want.
Part 3 · Objects

JSON — how data travels between layers

live · edit and run
const job = { id: 101, company: "Nimbus Labs", skills: ["React"] };

const text = JSON.stringify(job);   // object → text, to send
console.log(text, "—", typeof text);

// indented, for people to read
console.log(JSON.stringify({ id: 101, remote: true }, null, 2));

const back = JSON.parse(text);      // text → object, on arrival
console.log(back.skills[0], back === job);

const lossy = { when: new Date(0), note: undefined, score: NaN };
console.log(JSON.stringify(lossy));

try {
  JSON.parse("{ company: 'Nimbus' }");   // not valid JSON
} catch (e) {
  console.log(e.name, "—", e.message);
}
  • JSON is text. Every API call sends a string; JSON.parse turns it back into objects. fetch's res.json() does exactly this.
  • JSON is stricter than JavaScript: keys in double quotes, no single quotes, no trailing commas, no comments.
  • Only plain data survives. Functions and undefined vanish, Dates become strings, NaN becomes null.
  • Wrap JSON.parse in try/catch when the text comes from outside — a broken response should show a message, not crash the page.

Part 4 · Real data, shaped

The performance question you will be asked

live · edit and run
const n = 10000;
const all = Array.from({ length: n }, (_, i) => "u" + i);
const picked = Array.from({ length: n }, (_, i) => "u" + i * 2);

// a search inside a loop: n × n checks
let t = performance.now();
const slow = all.filter(a => picked.includes(a));
const slowMs = Math.round(performance.now() - t);

// build a lookup once, then each check is one step
t = performance.now();
const lookup = new Set(picked);
const fast = all.filter(a => lookup.has(a));
const fastMs = Math.round(performance.now() - t);

console.log("includes:", slow.length, "matches,", slowMs, "ms");
console.log("Set:     ", fast.length, "matches,", fastMs, "ms");
  • includes, indexOf and find walk the list from the start. Inside another loop, that is a list times a list — up to ten thousand times ten thousand checks.
  • A Set or an object indexed by id answers "is it there?" in one step, however large it grows.
  • A Map is the right tool when keys are not plain text, when you add and remove often, or when you need .size — object keys are always turned into strings.
Say it in the interview: "the first version is O(n²) because includes is linear inside a loop; building a Set first makes it O(n)." That one sentence is often the whole difference between a pass and a follow-up question.
Wrap-up

What to carry forward

  • Real data is an array of objects. Filter to choose, map to reshape, reduce to summarise.
  • Ask of every method: does it change the original? sort, push, splice do. toSorted, map, slice do not.
  • Give reduce a starting value — every time, without exception.
  • Arrow functions with braces need return, and an object literal needs brackets around it.
  • Objects are transformed through arrays: entries → map or filter → fromEntries.
  • Spread copies one level. For nested data, copy each level you change, or use structuredClone.
  • Never mutate state — add with spread, remove with filter, update with map.
  • A search inside a loop is O(n²). Build a Set or an index first.
